# eng-develop · 开发子技能

engineer 家族的**开发入口**。本技能写「开发」并**驱动状态回弹**。

## 依赖
- 沿用 `engineer` 锚点系统（Glob / Grep / 节点头部单行）。
- 对应 `§设计` 应已由 `eng-design` 产出**且经用户确认定稿**（见 `engineer` 第八节闸门）；若缺失或未确认，先回 `eng-design` 或提醒补，**不得擅自动工**。

## 职责：写哪一级的「## 开发」（模板见 engineer SKILL.md 第二节）
| 节点 | 写什么 |
|------|--------|
| `<模块>/MODULE.md §开发` | 开发日志(追加：日期·做了啥·关联功能锚点) / 阻塞风险 |
| `<模块>/<功能>/PROGRESS.md §开发` | 进度记录(追加：日期·进展，无状态列) / 实现笔记 |

## 流程
0. **闸门检查（确认定稿才开工）**：开工前必检对应 `PROGRESS` / `MODULE` 头部 `design` 字段是否为 `confirmed`。未确认（`design: -`）→ **立即停止**，提示「该节点设计尚未定稿，请先确认（可加载 eng-design）」，**不得写任何实现代码**；已确认（`design: confirmed`）→ 继续。
1. **定位活跃节点**：`Grep "active: true" engineer_doc/` 或用户意图确定当前开发焦点（某 PROGRESS / MODULE）。
2. **实现 + 自测**：写代码/实现功能，本地验证基本可用。
   - **UI 变更维护（仅当节点 `## 设计` 标了 eng-ui-tooling 能力）**：若给该节点新增/改动 UI（按钮、组件、页面、图表）——
     - 标了 **A 批注** → 给新增组件补 `data-ui="page.module.component"` 埋点（边界级：页面/模块/卡片/主要组件），并刷新批注映射，保证后续可按 `data-ui` 精准定位。
     - 标了 **B 内嵌可视化** → 同步更新该节点「可视化设计」子节（图表类型 / 数据形状 / 交互清单），保持设计=实现一致。
     - 未做同步视为本次开发不完整，**不得翻 `status: x`**。
3. **实时落盘**：
   - `PROGRESS §开发` 追加进度（日期·进展）；实现笔记记踩坑/关键代码位置。
   - `MODULE §开发` 追加开发日志（关联功能锚点）。
4. **功能完成 → 改状态 + 回弹（关键）**：
   - 该 `PROGRESS` 所有用例通过 → `Grep "F:xxx"` 命中头部 → `Edit status: ~ → x`。
   - 按 `engineer` 级联规则 3.3②：判本模块下所有 `PROGRESS` 头部是否全 `x` **且** `MODULE §测试` 用例全通过 → 是则把 `MODULE` 头部翻 `x`。
   - 按 3.3③：判所有模块头部是否全 `x` → 是则把 `GLOBAL` 头部翻 `x`。
5. **切换**：开发完成 → 切活跃节点到测试，提示加载 `eng-test`。

## 不做
- 不写 `§设计`（eng-design）/ `§测试` 用例主体（eng-test 写；本技能可先留占位）。
- 不绕过闸门：设计未确认定稿前绝不开始实现。
- git：按 `engineer` 第七节，若 `eng-design` 阶段已确认 git 跟进，在检查点提交（提交信息带锚点，如 `[auth] 登录功能完成 F:auth.login`）。
