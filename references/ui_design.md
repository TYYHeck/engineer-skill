# UI 可视化设计机制

## 目标

UI 参与度为 **① 精细 / ② 逐页 / ④ 风格** 时，用"静态预览批注 + 可编辑打磨"替代纯文字讨论，让用户**对着真实页面右键批注**，而不是脑补或用文字描述位置。

## 预览落盘（静态构建，不是手工复刻）

- **载体 = 真实 UI 的静态构建产物**：data-ui 埋点写进真实组件（React/Vue/纯 HTML 属性均可）→ `vite build` 出 dist → `vite preview` 起服务 → 浏览器打开 `dist/?annotate=1` 即批注界面。
- **禁止手工复刻一份 HTML 当批注板**（双维护成本高、易漂移、token 浪费——ui-byte-canvas 曾做 annotate.html 300+ 行×多次重写，已废弃）。
- 若目标是纯静态页面（无框架），直接在该页面埋 data-ui + 引入批注脚本，同样满足。
- 结构：
  ```
  ui-preview/               # 预览资产（构建产物 + 截图 + 批注说明）
  ├── dist/                 # vite build 产物（批注界面 = 真实 UI）
  └── README.md             # 批注流程说明（如何起 preview、如何批注、如何导出）
  ```
- **每个可批注元素埋 `data-ui`（层级点分路径）+ `data-label`（人类可读名）**：
  - `data-ui` = `区域.模块.子组件`（如 `titlebar.menu.edit`、`canvas.toolbar.move`），**与代码结构一一对应**，AI 拿到路径直接定位代码；
  - `data-label` 给人看（批注窗口标题用），如 `data-label="工具栏-移动（十字箭头）"`；
  - **全局唯一**，禁止 `btn-1`/`box-2`（AI 无法映射到代码）；容器级埋一个兜底即可（脚本向上找最近 data-ui 祖先）。

## 批注闭环（定稿标准：静态预览 + 悬浮工具栏 + 右键单批注）

- **悬浮批注工具栏**（固定右上角，可收起）：`[批注 N 条] [导出 JSON] [复制] [清空] [✕]`；
- **右键任意 [data-ui] 组件 → 弹出批注窗口**（预填 ui 路径 + label + textarea）；用右键不用左键——左键被页面自身交互占用，右键是天然批注意图；
- **一个组件只能有一个批注**（按 data-ui 唯一键）：
  - 无批注 → 新建（取消 / 保存）；
  - 已有批注 → **再次右键显示当前批注**（编辑模式：删除 / 取消 / 更新，预填原文本，标题"已有批注（编辑中）"）；
- 数据存 **localStorage**（key `ubc-annotations`，`Record<ui, Annot>`）——刷新不丢；「复制」写剪贴板（clipboard → execCommand 兜底）；
- 数据契约：`[{ ui, label, text, time }]`（单组件单批注 → 按 ui 索引，无 id 冲突）；
- **批注层默认启用**（开发/预览阶段），`?annotate=0` 可关；
- **hover 高亮（双向定位）**：鼠标悬停带 `data-ui` 元素 → 细边框提示（已有批注 → 主题色高亮边框 + 角标）；悬停批注列表项 → 页面对应元素高亮——**所见即所批**；
- **AI 修改流程（强制：AI 不查看网页）**：收批注 JSON → 按 `ui` 路径定位代码 → 每条一次精准 Edit → 用户刷新看新版 → 处理完清空。**AI 全程不打开/不查看网页、不截图、不 DOM 探测**——只根据批注的 ui 路径理解并修改。完整循环：**AI 生成预览 → 用户批注 → AI 按批注修改 → 用户查看**，AI 永远不需要看网页。

### 独立模板（注入任意页面即可用）

- `assets/annotate.js`：**纯脚本批注层模板**（原生 JS + CSS 内联注入，~200 行），注入任意静态页面即获得上述全部批注能力（悬浮工具栏/右键单批注/localStorage/导出复制）；
- 使用：目标页面每个可批注元素埋 `data-ui` + `data-label` → `<script src="annotate.js"></script>` → 打开页面右键批注；
- React/Vue 项目可参考 `ui-byte-canvas/packages/editor/src/annotate/AnnotateLayer.tsx`（组件版同逻辑）；

## 可编辑打磨（控制面板，保留不降级）

- 三档（精细/逐页/风格）都保留**带控制面板的交互式预览**：滑杆 / 取色器 / 选择器调整字号、间距、圆角、颜色、主题，用户**直接操作即改**（调参）；
- 控制面板管"调参"，批注管"指出位置改什么"，两者互补；
- 位置调整：布局用可调节参数（flex / grid 数值），用户给目标或点选，AI 同步改 theme.css。

## 精细档逐组件设计循环（硬约束）

**UI 参与度 = ① 精细时强制走此循环**，禁止一次生成全部页面/组件。三层粒度，逐层确认后才进下一层：

```
⓪ 全局骨架（先定全局，再进细节）：整体背景色 → 分栏布局（侧栏/主区/顶栏框架）→ 页面框架
    预览：骨架级 HTML（布局框 + 背景/分栏占位）→ 确认
① 组件级：每个子组件单独走（如 导航栏 → 内容体 → 每区组件）
    预览：components/<组件>.html（片段级，几十行，比整页小 3-5 倍）
    讨论：选项化提问该组件样式参数（布局 / 配色 / 字号 / 间距 / 状态）
    确认：控制面板可调 + 批注反馈 → 用户说 OK 才放行下一个
    → 样式变量增量写 theme.css（短锚点 Edit）
② 页面组合：该页组件全过 → 组合整页预览 → 协调检查（间距 / 层级 / 视觉平衡）→ 确认
③ 全局回归：所有页完成 → 主界面回归（导航一致性 / 主题统一）→ 确认
```

- **骨架定义**：UI 设计骨架 = 从**整体背景色**到**分栏布局**，再到**每个页面的细分设计**——自上而下，先全局后局部。

- **每个组件必须有 预览 + 讨论 + 确认 三件套**才放行；"简单问一下"不算讨论（讨论 = 针对具体样式参数的选项化提问）；
- **结案护栏**：设计块收尾必须给 **UI 确认清单**（组件级已确认列表 / 页面组合已确认 / 全局回归结果），**未完成全部确认不得进入开发块**；用户明确说"先开发"才放行。

## 迭代收敛（不设硬轮次上限）

- 迭代轮次**不设硬上限**（真实修改次数不可预测）；
- 但同一页迭代**超 5 轮**时提示一次："锁定布局只调样式 / 继续改"——节奏提醒，不强制打断。

## 参考搜索（精美 UI）

- 需要灵感时用 **WebSearch** 搜索设计参考（配色、布局、组件规范，如 dribbble / behance / 组件库官网）；
- 参考**本机其他 UI 相关技能/模板**（如 ui-design-studio、design-token 等），提取可复用规范；
- 把参考**提炼成样式变量**（色板 / 字号 / 间距 / 组件状态），落到 theme.css；**不整段照抄**。

## token 优化（UI 批注强制项）

- **AI 不看网页（强制）**：AI 修改只按批注 `ui` 路径定位代码，**禁止截图、禁止打开浏览器、禁止 DOM 探测**——网页是给用户看的，AI 只看代码与批注；
- **一套 UI 一处维护**：真实组件埋 data-ui + 静态构建 = 批注界面即真实产品界面，改一次 UI 批注界面自动同步；
- **大文件用 Edit 增量改**，不用 Write 全量重写；
- **data-ui 即定位锚**：AI 收批注直接按路径 Edit，不需要读全量代码定位组件。

## 产出落盘与衔接

- 设计块：预览构建 + `theme.css` 留在 `ui-preview/`，作为**项目 UI 原型资产**（可保存、可给团队看）；
- 开发块：引用 `theme.css` 样式变量进 `src/`（转化为目标框架的 token/变量文件），**不在开发块重复预览已定稿的页面**；新增页面或大改时按需开预览；
- UI 讨论记录写入 `project_plan/ui.md` 或 `<点>/process.md`。
