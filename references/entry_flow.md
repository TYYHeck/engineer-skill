# 通用入口流程（开发块 / 测试块共用）

## 入口动作（按序）

1. 读 `project_plan.md` + 对应 `mode.md`（存在则复用：确认"还是这个模式吗"，用户说变了才更新）。
2. **并行问 2 个问题**（一次出，各带选项 + 自定义输入）：
   - **执行模式**（单选）：
     - ① 单点逐个做（讨论 → 实现 → 下一个）；
     - ② 先讨论到一部分/全部 → 自动做；
     - ③ 全自动（AI 按清单自动做完，统一汇报）。
   - **疑问处理**（单选，三个模式都问）：
     - ① 全按 AI 推荐（最后列"按默认处理清单"供抽查）；
     - ② 关键疑问才问（数据结构 / 成本 / 合规 / 对外承诺）；
     - ③ 有疑问就问。
3. **范围**：仅当选了模式②时追加问——列出模块批次让用户选（① 模块1 ② 模块1~2 ③ 全部 ④ 自定义），敲定后自动实现该范围，完成后再问下一段。
4. 配置写入 `mode.md`（模板见 assets/mode_template.md，AI 直接写，不用问）。

## 逐点执行骨架（模式①②③通用）

1. 建 `<模块>/<点>.md`（点主文档，模板见 assets/point_template.md）：先判**起点**——
   - 该点有设计需求（主文档未写）→ 状态 **待设计 → 设计中**，写主文档；
   - 无（修复/重构/已有设计）→ 状态直接从 **开发中** 开始。
2. 实现代码（状态在上下文跟进）；**点结束时更新一次** `<点>/work.md`（任务表格 + 状态流转）。
   - 含 UI 实现的功能：先落盘预览页（`ui-preview/`，带 data-ui 埋点 + 批注脚本）→ 用户点批注/调控制面板 → AI 按批注精准修改 → 定稿后再写代码（详见 references/ui_design.md）。
3. **自测**：跑通 → 状态 **测试中 → 通过**（开发自带自测，不必等测试块）。
4. **批次回写**：本批结束时统一在 `project_plan.md` 标【通过】点 + 批量追加「变更日志」（不逐点回写）。
5. **停滞**：被阻塞时标 `停滞（原因：… / 阻塞点：…）`，解锁后回原状态继续。

## 轻量档差异

- 无 `<点>.md` / `<点>/work.md` 嵌套：功能清单即任务清单，`project_plan.md` 内【状态】就地更新。
- 状态只有 待做 / 进行中 / 通过（+停滞）。
