# 设计块流程

## 目标

设计主体项目结构（粗略框架），产出总设计文档 `project_plan.md`，各部分的讨论记录写入 `project_plan/` 同名文件夹；总设计不写点级细节（留给开发块）。

## 步骤（按序）

1. **项目位置**（**先做，决定名字问法**）：当前工作区文件夹为项目根 / 新建项目根文件夹（可能需要创建目录）。
2. **项目名**（**依赖步骤 1，位置定了才问**）：
   - 以当前工作区为根 → 问**实际中文名**（可不取中文名）；
   - 新建项目根 → **必须有英文名**（作文件夹名，如"AI IDE"→ `ai-ide`）。
   - 同时先建 `engineer_doc/` + `project_plan/` 空骨架（讨论记录有处可写）。
   - **git 询问**（开始就问）：需要 git 版本管理吗？需要 → `git init` + `.gitignore`（`engineer_doc/`、`ui-preview/` 提交；`node_modules`、`dist`、`target`、`.idea` 等排除）+ 初始 commit；之后每块/每批结束提交一次（详见 SKILL.md「git 集成」）。
3. **项目底层与技术栈**（无依赖问题可一批问）：
   - **目标平台**（专业用语，不用"端"）：Web / 移动 / 小程序 / 桌面 / 后端 / CLI，**可多选**；
   - **技术栈**：用户没说才问；**单选**（① AI 推荐一套（按层：语言/后端/前端/数据库/中间件/部署）② 备选 2 套 ③ 逐层单独讨论 ④ 自定义）；是否用 Docker 等容器化看用户选择；
   - **部署目标**；
   - **交付质量**：4 档单选——演示 / 标准 / 精细 / 旗舰级（安全、并发、性能全按最高标准）；可附加"详细讨论"选项（选中则展开安全/性能深入讨论）。
4. **设计方式**：总框架 + 细化 / 逐步开发（主界面 → 分界面）。
5. **功能清单**（**硬步骤，不得跳过、不得自行决定**）：
   - 必须给出**分模块推荐清单**（AI 按交付质量从简单到详细推荐，可分多组）；
   - 必须让用户**多重多选框勾选**确认——不得按推荐全做、也不得自拟清单跳过确认；
   - **最后**才问"还有没有其他功能"；
   - **不做每个点的详细设计**（留到开发块的点点主文档）。
6. **定档**（AI 推荐 + 用户确认）：此时**交付质量（步骤 3）与点数（步骤 5）信号已齐**，推荐 轻量 / 标准 / 旗舰（详见 references/doc_system.md）：
   - 交付质量：演示 → 轻量；标准 / 精细 → 标准；旗舰级 → 旗舰；
   - 点数：≤5 → 轻量；5~15 → 标准；>15 → 旗舰；
   - 两信号冲突**取高者**；用户可改。
7. **UI 需求**（**按档位问**）：
   - 轻量档：**跳过/简化**——只问一句"要不要界面风格"，不做参与度/可视化预览；
   - 标准/旗舰档：**UI 参与度** 5 档单选：① 精细（可视化 UI 设计，每个控件位置都问）② 逐页（每页组成+关键交互）③ 中等（页面清单+整体感觉）④ 风格（关键页+风格方向）⑤ 简单（全交 AI）；**视觉风格**：推荐/建议/询问 模式；
   - **落盘预览 + 批注交互**（精细/逐页/风格档）：预览页落盘到 `ui-preview/`（每页一个 HTML + theme.css + 批注脚本），用户浏览器打开、点元素批注、一键复制批注文本给 AI，AI 精准修改；详见 references/ui_design.md；
   - **精细档硬约束**：必须走**逐组件设计循环**（组件 → 页面组合 → 全局回归 三层逐级确认），**禁止一次生成全部页面/组件**；每个组件必须有 预览 + 讨论（选项化提问样式参数）+ 确认 三件套才放行下一个（详见 references/ui_design.md）。
8. **初始化文档（按档位）**：
   - 轻量档：只建 `project_plan.md`（lite 模板，见 assets/project_plan_lite_template.md）；
   - 标准/旗舰档：补建 `develop/`、`test/`（按需）骨架 + `project_plan.md`（模板见 assets/project_plan_template.md）——功能清单刚确认完，**一次写全**，不留空模板回头补。
9. **收尾**：汇总写 `project_plan.md`（项目基础 / 目标平台 / 技术栈 / 设计方式 / 功能清单（带【状态】标注）/ UI 需求），各部分讨论记录写入 `project_plan/` 对应文件并标状态；块结束给摘要 + 继续/停下/换块。
   - **UI 硬护栏（精细档）**：UI 参与度=精细时，收尾必须给出 **UI 确认清单**（组件级：已确认组件列表 / 页面组合：已确认页面 / 全局回归：结果），**未完成全部确认不得进入开发块**；用户明确说"先开发"才放行。

## 轻量档差异

- 步骤 3 只问**技术栈 + 交付质量**（跳过部署目标；平台/技术栈决定即可），跳过步骤 4 设计方式、步骤 7 简化；
- 文档只有 `project_plan.md`（lite 模板）：功能清单即任务清单，每行带【待做/进行中/通过】状态，后续开发就地更新，不建 `<点>/work.md` 嵌套。

## 明确不做

- 范围边界（只按用户说的做，边界由功能建议自然带出）
- 架构草图
- 里程碑（顺序由开发块按功能清单自然推进）
