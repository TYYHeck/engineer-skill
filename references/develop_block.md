# 开发块流程

## 入口

- 通用入口（模式 / 疑问处理 / 范围 / mode.md 写入）→ **见 references/entry_flow.md**。
- 入口前置：读 `project_plan.md`（确认功能清单与状态）。

## 实际项目目录

- 开发块负责**建实际项目目录**（`src/` 等，按技术栈初始化）与基础配置——这些不在 `engineer_doc/` 内。

## 逐点执行

逐点执行骨架见 **references/entry_flow.md**（建点 → 起点判定 → 实现 → 自测 → 批次回写），开发块特有强调：

- **点主文档**：`<模块>/<点>.md` 含 功能说明 / 接口设计 / 数据结构 / 涉及平台；细节逐个确认（问法按疑问处理策略）。
- **含 UI 实现的功能**：先落盘预览页（`ui-preview/`，data-ui 埋点 + 批注脚本）→ 用户批注/调控制面板 → AI 精准修改 → 定稿再写代码（详见 references/ui_design.md）。
- **停滞**：被阻塞时标 `停滞（原因：… / 阻塞点：…）`，解锁后回原状态继续。

## work.md 是状态唯一事实源

- 每个 `<点>/work.md` 含 YAML frontmatter（point / 性质 / platform / status）+ 任务表格 + 状态流转记录；**点结束时更新一次**（状态降频省 token，中间状态留在上下文）。
- `project_plan.md` 功能清单 **批次回写**（本批结束统一标通过 + 批量追加变更日志）。
- 轻量档：无 `<点>/work.md`，直接在 `project_plan.md` 功能清单【状态】就地更新。
