# 开发块流程

## 入口（进块先做）

1. 读 `project_plan.md` + `develop/mode.md`（存在则复用，或问"还是这个模式吗"）。
2. **开发模式**（单选）：
   - ① 单功能逐个做（讨论 → 实现 → 下一个）；
   - ② **先讨论到一部分/全部 → 自动做**；
   - ③ 全自动（AI 按清单自动做完，统一汇报）。
3. **疑问处理**（通用，三个模式都问，存 `develop/mode.md`）：
   - ① 全按 AI 推荐（最后列"按默认处理清单"供抽查）；
   - ② 关键疑问才问（数据结构 / 成本 / 合规 / 对外承诺）；
   - ③ 有疑问就问。
4. **模式②确认范围**：列出模块批次让用户选（① 模块1 ② 模块1~2 ③ 全部 ④ 自定义），敲定后自动实现该范围，完成后再问下一段。
5. 配置写入 `develop/mode.md`（模板见 assets/mode_template.md）。

## 实际项目目录

- 开发块负责**建实际项目目录**（`src/` 等，按技术栈初始化）与基础配置——这些不在 `engineer_doc/` 内。

## 逐功能执行（以 `<点>` 为单位，模式①②③通用）

1. 状态：**待设计 → 设计中**（无设计需求的任务类型如"实现/修复"直接从 待开发 开始）。
2. 建 `<模块>/<点>.md`（功能开发文档，模板见 assets/point_template.md）：功能说明 / 接口设计 / 数据结构 / 涉及平台；细节逐个确认（问法按疑问处理策略）。
   - **含 UI 实现的功能**：先渲染交互式预览（含控制面板）→ 打磨位置/样式 → 定稿后再写代码（详见 references/ui_design.md）。
3. 状态：**待开发 → 开发中**：实现代码，边做边更新 `<点>/work.md`（任务表格 + "相关文件"字段）。
4. **自测**：跑通 → **待测试 → 测试中 → 通过**（开发自带自测，不必等测试块）。
5. **收尾回写**：`project_plan.md` 功能清单中该点标【通过】。
6. **停滞**：被阻塞时标停滞（原因可选），解锁后回到原状态继续。

## work.md 是状态唯一事实源

- 每个 `<点>/work.md` 含 YAML frontmatter（point / module / type / platform / status / owner / created）+ 任务表格 + 相关文件 + 状态流转记录。
- `project_plan.md` 只在收尾（通过/停滞）时回写。
