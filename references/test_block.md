# 测试块流程（按需）

## 触发场景（用户需要时才进入）

- 优化验证、修复 bug、补充测试用例、专项/深度测试（如旗舰级安全/性能测试）。
- **全流程不自动进测试，也不强制问**；用户提到相关需求（"修个 bug" / "加些测试用例" / "测一下" / "跑起来报错"）时进入。

## 入口

1. 读 `project_plan.md` + `test/mode.md`。
2. **测试模式**（单选）：① 逐个功能测 ② 先讨论一批用例 → 自动执行 ③ 全自动。
3. **疑问处理**：同开发块通用（① 全按 AI 推荐 ② 关键疑问才问 ③ 有疑问就问），存 `test/mode.md`。
4. **范围**：模块批次（同开发块：① 模块1 ② 模块1~2 ③ 全部 ④ 自定义）。

## 逐功能执行

1. 建 `test/<模块>/<点>.md`（测试用例文档，模板见 assets/point_template.md）：
   - 用例列表：用例编号 / 前置条件 / 操作步骤 / 预期结果 / 优先级 / 涉及平台；
   - 用例按功能逐个**多重多选**确认（覆盖：正常 / 空态 / 交互 / 异常 / 细节，交付质量越高覆盖越全）。
2. 建 `<点>/work.md`：执行记录（每条用例 通过/失败/阻塞 + 状态标注）。
3. 执行用例 → 记录结果 → 状态流转：**待测试 → 测试中 → 通过**。
4. **发现 bug**：创建"修复"类型任务（`develop/<模块>/<点>.md` + work.md，状态 待开发），修复后**回归**对应用例 → 通过。
5. **收尾回写**：`project_plan.md` 功能清单对应点标【通过】。

## 平台标注

- 用例/任务记录带 `platform` 字段（web / mini / mobile，可多选）；bug 类标注问题出现的平台。
- **不按平台拆分文档**。
