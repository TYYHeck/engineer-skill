# 测试块流程（按需）

## 触发场景（用户需要时才进入）

- 优化验证、修复 bug、补充测试用例、专项/深度测试（如旗舰级安全/性能测试）。
- **全流程不自动进测试，也不强制问**；用户提到相关需求（"修个 bug" / "加些测试用例" / "测一下" / "跑起来报错"）时进入。

## 入口

- 通用入口（模式 / 疑问处理 / 范围 / mode.md 写入）→ **见 references/entry_flow.md**。
- 入口前置：读 `project_plan.md`。

## 逐点执行

1. 建 `test/<模块>/<点>.md`（测试用例文档，模板见 assets/point_template.md）：
   - 用例列表：用例编号 / 前置条件 / 操作步骤 / 预期结果 / 优先级 / 涉及平台；
   - 用例按点逐个**多重多选**确认（覆盖：正常 / 空态 / 交互 / 异常 / 细节，交付质量越高覆盖越全）。
   - **起点判定**：用例文档未写 → 状态 **待设计 → 设计中** 写用例；已有用例 → 直接从 **测试中** 开始。
2. 建 `<点>/work.md`：执行记录（每条用例 通过/失败/阻塞 + 状态标注）。
3. 执行用例 → 记录结果 → 状态流转：**测试中 → 通过**。
4. **发现 bug**：建修复点（`develop/<模块>/<点>.md` + work.md，起点无设计 → 直接从 **开发中**），修复后**回归**对应用例 → 通过。
5. **批次回写**：本批结束时统一在 `project_plan.md` 标【通过】点 + 批量追加「变更日志」（不逐点回写）。

## 平台标注

- 用例/任务记录带 `platform` 字段（web / desktop / mobile / mini，可多选）；bug 类标注问题出现的平台。
- **不按平台拆分文档**。
