# 状态机

## 状态（标准 / 旗舰档）

```
待设计 → 设计中 → 开发中 → 测试中 → 通过
                            ↘ 停滞（全程都可能）
```

- 每个点执行前**先建任务记录文档**（`<点>/work.md`），再按情况标状态。
- **起点只判一次**：该点有无设计需求——
  - 有（新点，点主文档未写）→ 从 **待设计** 开始：写主文档 → 设计中 → 开发中 → 测试中 → 通过；
  - 无（修复 / 重构 / 已有设计）→ 直接从 **开发中** 开始：实现 → 自测 → 通过。
- **停滞**：AI 或用户均可标注，格式 `停滞（原因：… / 阻塞点：…）`；解锁后回原状态继续。

## 轻量档状态

```
待做 → 进行中 → 通过
         ↘ 停滞
```

- 单文档内嵌：`project_plan.md` 功能清单【状态】就地更新，不建 `<点>/work.md`。

## 状态管理规则

1. **`<点>/work.md` 是状态唯一事实源**：AI **每个点结束时更新一次**（状态降频省 token；中间状态留在上下文跟进，不逐操作落盘）。
2. **`project_plan.md` 功能清单【状态】批次回写**：每批次（或收尾）结束**统一回写**本批通过/停滞的点，并**批量追加**「变更日志」；其余状态一律看 work.md。**不逐点回写**（省 token）。
3. **开发自带自测**：自测通过即可标"通过"，不必等测试块。
4. 块级看板（如 `index.md`）只是汇总视图，不替代 work.md。
5. **项目收尾**：所有点通过 / 用户验收 / 用户说"完成"时，填 `project_plan.md` 收尾总结（完成情况 / 遗留问题 / 如何运行）。

## 落盘操作规范（读取与回写统一，省 token）

锚点 = 模板固定的 YAML 键（如 `status:`）与区段标题（如 `## 5. 功能清单`）——唯一、不受内容增长影响。

1. **回写优先用锚点**：old_string 用最短稳定锚点行，会话内记忆直接 Edit，不读全文；
2. **记忆不可靠时锚点核验**：上下文压缩 / 多轮编辑 / 疑似外部修改 → Grep 锚点（`-n -A1`）只取目标行内容，对上了直接 Edit；
3. **仍不一致才 Read 全文**：锚点核验也失败（文件结构被改）→ 才 Read 该文件全文兜底；
4. **跨会话**：首次操作某文件 → 优先 Grep 锚点核验头部，确认结构未变；变了才 Read 全文；
5. **Edit 回显校验**：确认改动生效（status 变成目标值）；异常走 2/3。

## 性质（可选备注，不参与流程）

- `work.md` 里可留一行**性质**：新功能 / 修复 / 重构——给人看的备注，**不参与任何状态判断**，可写可不写。
