# 能力 B：内嵌式可视化设计（前端）· 设计模板

本文件是 `eng-ui-tooling` 能力 B 的**按需详档**。仅在用户选定「内嵌式可视化设计」时由 `eng-ui-tooling` 加载；SKILL.md 只做能力描述，不内联本内容。

## 一、何时用
在页面**内联**图表 / 图解 / 可视化组件，而非跳转到独立看板。典型场景：
- 数据看板（指标卡、趋势线、占比环）
- 流程/状态图（步骤条、状态机、依赖关系）
- 空间/结构可视化（树、拓扑、热力）

## 二、设计四问（写进 §设计 前先定）
1. **数据类型**：时序 / 分类占比 / 层级 / 网络 / 地理？决定图表类型。
2. **渲染选型**：
   - 轻量静态 → SVG（手写或组件库如 Recharts/ECharts）。
   - 高频动态 → Canvas（如大量节点/实时流）。
   - 交互复杂 → 图表库（ECharts/D3/Visx），避免自造轮子。
3. **数据来源**：静态 mock / 接口拉取 / 实时推送（WebSocket/SSE）？约定数据形状与刷新频率。
4. **交互深度**：悬停 tooltip / 下钻 / 筛选 / 导出？列清楚，避免范围蔓延。

## 三、数据结构模板（与后端/接口对齐）
```ts
interface VizDatum {
  id: string;
  label: string;
  value: number;          // 或 children/edges，按类型
  group?: string;         // 分类/分色
  ts?: string;            // 时序用
}
// 约定：前端只消费稳定形状的数组，格式化/聚合在前端做，后端只给原始记录
```

## 四、组件结构（落地形态）
```
<功能>/
├── VizPanel.tsx          # 容器：布局 + 标题 + 筛选器
├── charts/
│   ├── TrendChart.tsx     # 时序
│   └── ShareDonut.tsx     # 占比
└── useVizData.ts         # 数据 hook：拉取/聚合/刷新
```
- 每个图表组件**单一职责**，数据通过 props 传入，便于复用与测试。
- 大图/重图用 `React.memo` + 按需渲染，避免窄屏变形（遵循防挤变形约定：`white-space:nowrap` + `flex-shrink:0` + `overflow-x:auto`）。

## 五、与 engineer_doc 对接
- 设计产物写进对应节点 `## 设计` 的「可视化」子节（或专门 PROGRESS）。
- 记录：图表类型选型理由、数据形状、交互清单、渲染选型。
- 状态/头部遵循 `engineer` 锚点系统；本能力只写设计，实现交 `eng-develop`。

## 六、确认闭环（perfect-design 式）
出草稿 → `AskUserQuestion` 多选题确认（图表类型/交互范围/数据来源）→ 未确认不写实现代码 → 定稿才交 `eng-develop`。

## 七、维护：新增图表 / UI 时同步更新可视化设计（贯穿项目生命周期）

能力 B 启用后贯穿整个项目：后续该节点每加一个图表 / 可视化 UI，都必须同步更新「可视化设计」子节，否则设计文档与实现漂移。

**规则**
- 新增图表 → 在节点 `## 设计` 的「可视化」子节补：图表类型 + 选型理由 + 数据形状（`VizDatum`）+ 交互清单。
- 数据形状变更（字段增删）→ 同步更新 `VizDatum` 约定与 `useVizData.ts` 的消费逻辑。
- 由 `eng-develop` 执行（见 `eng-develop` 流程 2 的 UI 变更维护）；未同步视为开发不完整，不得翻 `status: x`。
