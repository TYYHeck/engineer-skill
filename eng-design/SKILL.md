# eng-design · 设计子技能

engineer 家族的**设计入口**。本技能**只写「设计」**，不碰开发与测试。

## 依赖
- 必须先有 `engineer` 技能的锚点系统（Glob 取树 + Grep 取状态 + 节点头部单行）。本技能**不重复**锚点规范，直接沿用。
- 首次进入前确认 `engineer_doc/` 已初始化（GLOBAL.md / DISCUSS.md / 首个 MODULE.md）。若未初始化，先回 `engineer` hub 走初始化流程。

## 职责：写哪一级的「## 设计」（模板见 engineer SKILL.md 第二节）
| 节点 | 写什么 |
|------|--------|
| `GLOBAL.md §设计` | 项目目标 / 范围(in·out) / 技术栈 / 模块清单(slug·职责) / 关键约束 |
| `<模块>/MODULE.md §设计` | 模块目标 / 子任务拆分(链 PROGRESS 锚点) / 接口契约 / 模块内协作分工 / 依赖 |
| `<模块>/<功能>/PROGRESS.md §设计` | 功能描述 / 验收标准(可验证) / 方案要点 |

## 流程
1. **定位活跃节点**：`Grep "active: true" engineer_doc/` 找当前设计焦点；若无，从 GLOBAL 开始或由用户意图确定。
2. **写设计**：
   - 全局设计 → 填 `GLOBAL.md §设计`，并把模块清单与关键决策同步进 `DISCUSS.md`（记录来源/依据，防讨论中断丢事实）。
   - 模块设计 → 建 `<模块>/MODULE.md`，`§设计` 拆子任务、每条链 `PROGRESS` 锚点；依赖别的模块用 `M:<slug>` 链。
   - 功能设计 → 建 `<模块>/<功能>/PROGRESS.md`，`§设计` 写功能描述 / 验收标准 / 方案要点。
3. **git 跟进确认（设计阶段，不再初始化时问）**：写 GLOBAL 设计背景时，询问用户「是否用 git 全程跟进本项目？」并说明利弊（见 `engineer` 第七节）；同意则记录进 GLOBAL 备注，后续检查点提交带锚点。
4. **UI / 交互设计（内部分支）+ 按需可视化能力**：遇到前端 UI 密集的模块/功能：
   - 先按清单写 UI 设计进对应 `§设计`：页面/组件树、布局结构、关键交互流、状态管理、视觉规范要点、设计稿/原型链接（若有）。
   - **询问是否启用可视化/调试能力**（perfect-design 式，不默认开）：用多选问用户要不要「可视化 DEBUG-HTML 批注（前端+后端）」/「内嵌式可视化设计（前端）」。
   - 用户选「是」→ 用 Skill 工具**按需加载 `eng-ui-tooling`** 接管该部分设计；选「否」→ 不加载，继续普通 UI 设计。
   - **能力标记（贯穿维护）**：无论启用 A / B，都须在该节点 `## 设计` 写一行能力标记（如 `UI 可视化能力：A 可视化批注` / `B 内嵌可视化`），供后续 `eng-develop` / `eng-test` 识别并持续维护（规则见 `eng-ui-tooling`「UI 能力标记与贯穿维护」）。
   - **交互实测询问（非默认，见 `engineer` 8.5）**：UI 设计默认**不起运行环境、不截图、不读页面**做"验证"；若用户想「实际跑起来看效果 / 试交互」，**先询问**再按其指示执行（明确要求起 dev server / 截图 / 点流才做），未获准一律不尝试。
5. **确认定稿门（perfect-design 式，关键）**：每产出一份设计，向用户**呈现设计摘要 + 用多选题确认**；用户未确认前**不进入开发**，要求调整则回到设计修改后再确认（见 `engineer` 第八节）。**确认后**：把该节点头部 `design: -` 改为 `design: confirmed`（持久标记，供 `eng-develop` 开工闸门跨会话验证）。
6. **实时落盘**：每确定一点立即写回对应文档，不攒批；新建节点时头部写 `status: ~`。
7. **切换**：设计**经用户确认定稿** → 把活跃节点 `active` 切到下一阶段（开发），提示用户加载 `eng-develop`（或由 `engineer` hub 路由）；eng-develop 受「确认定稿才开工」闸门约束。

## 不做
- 不写 `## 开发` / `## 测试`（交给 `eng-develop` / `eng-test`）。
- 不把头部 `status` 翻到 `x`（开发完成才翻，属 `eng-develop` 职责；本技能新建节点只写 `~`）。
- 不绕过「确认定稿才开工」闸门：设计未经用户确认定稿，不提示进入开发、不代用户点确认。
- **不擅自动用截图 / 浏览器读取运行页面来"验证"设计**（见 `engineer` 8.5）；UI 设计默认产出设计稿 / 组件树 / 交互流等静态设计，需要实测必须先问用户。
